# 0028：安全边界与漏洞依赖修复

日期：2026-10-11。状态：已采用。任务：FN-68。

- SMB 与播放器/诊断共用凭证脱敏。引号值用逐字符扫描处理转义、换行和未闭合输入；裸 VLC 凭证选项保守隐藏本行后续内容，以覆盖密码内空格。URI 用户信息覆盖仅用户名及原始 `@`。不把正则当成任意秘密识别器，业务仍禁止记录原始凭证。
- 诊断缓冲保留 200 条，同时限制消息 4096 字符、标签 128 字符。先脱敏再截断，避免截断破坏引号边界。播放器异常日志和服务器验证/状态/安全错误也必须脱敏。
- Vosk ZIP 目录必须为空；拒绝携带数据的目录条目，防止 `closeEntry()` 自动排空时绕过累计解压上限。固定模型 SHA-256、下载上限和原子 ready 策略不变。
- 仅为已确认的依赖安全公告增加 app 约束：ML Kit 间接 OkHttp 3.0.0 → 4.12.0、Okio 1.6.0 → 3.6.0（JVM 变体同版本）；SMBJ 间接 bcprov-jdk18on 1.79 → 1.85。不全局注册或替换 Android 的系统安全提供者。
- 新解析的 13 个二进制/元数据逐一从 Maven Central 重取核对 SHA-256，原有摘要不改、不添加跳过例外，CI/发布仍严格验证。新增 Kotlin jdk7/8 1.9.10 产物是兼容桥接 JAR，实际 Kotlin stdlib 仍为 2.4.0。

这是对决策 0025 的补充。已知漏洞扫描命中说明依赖存在受影响代码，不能推断这些公告在当前 SMB/翻译调用路径均可被利用。升级后的 Android SMBJ MD4/CMAC 已知向量、CCM/GCM 往返及篡改拒绝、HTTP/Okio 链接检查覆盖二进制兼容风险；不等同于真实 NAS 联调或所有原生解码器审计。
