# 决策：拖动预览画面、全屏横屏与手势快进

- 状态：accepted
- 日期：2026-08-23
- 任务：FN-48

## 问题

决策 0007 规定进度条拖动期间只更新本地 UI，松手后才发一次 seek。真机上这会让用户拖着进度条却看不到目标画面。用户现在明确要求：

1. 手指还按在进度条上时，画面就要跟到当前拖到的位置；松手后停在该点。
2. 提供全屏按钮，点击后直接横屏，不必先把手机转过去。
3. 播放画面上从左往右滑可以快进，从右往左滑可以后退。

## 证据

- 0007 否定连续 seek 的原因是当时产品路径仍可能走 `ProxyFileDescriptor`，快速 `setTime` 会让 NAS 随机读重叠，并触发厂商 AppFuse 断连。
- 当前产品播放已统一为 libVLC direct SMB（0007 决定 1、4），本地文件仍走 precise seek。paused seek 已有 `SeekPreviewSession` 单会话改目标。
- 0007 决定 1/3/4/5（direct SMB、硬解、无运行时 fallback、proxy FD 仅用于缩略图/听译）仍然成立，本决策只改交互层的 seek 节奏。

## 决定

1. **拖动预览**：slider 与水平滑动在按下期间按 160ms / 400ms 门槛发送 preview seek；松手再提交一次当前落点。SMB 仍用 `setTime(..., true)`，本地仍用 precise seek。暂停态继续复用同一个 preview session，不反复 play/pause。
2. **不覆盖画面**：用户正在拖动或滑动时不显示“正在定位”与缓冲层，避免把刚解码的预览帧挡住。
3. **全屏横屏**：全屏按钮请求 `SCREEN_ORIENTATION_SENSOR_LANDSCAPE`；退出全屏请求 `SENSOR_PORTRAIT`。离开播放页仍恢复 `UNSPECIFIED`。全屏请求优先于方向锁。
4. **手势快进**：水平滑动映射为相对当前进度的时间偏移（满宽最多 90 秒，短片用片长）；垂直滑动仍是亮度/音量；单击与双击逻辑不变。锁定控制时手势仍被吞掉。

## 未选择的方案

- 恢复 0007 之前“每个 pointer 都 seek / 松手 precise”：会重新制造重叠随机读。
- 拖动只改本地 UI：无法满足“手没放开也要看到画面”。
- 用系统自动旋转代替全屏按钮：手机竖着拿时无法立刻横屏。

## 后果

- 决策 0007 第 2 点（拖动期间不发 seek）被本决策替代；其余 SMB 路径决定不变。
- 弱网 / 未完成文件上的快速预览仍可能落到附近关键帧或短暂缓冲；松手落点仍以最后一次 seek 为准。
- 未做新的 SMB 缓存层，也未改凭证传递方式。
