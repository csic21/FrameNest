# 0024：本机听译测量与保守静音实验

## 状态

FN-62，2026-10-10。保留 FN-61 的默认模型、3 秒窗口和 750ms 上下文；实验默认关闭。

## 背景与参考

参考 [Handy 固定版本](https://github.com/cjpais/Handy/tree/48a3d8e9ee456c1c6a3b7223779271c457890b4d) 的阶段测量、保留起声上下文、后端能力门控思路。这里独立实现，不复制 Handy 源码或打包其模型。未来若复制 MIT 代码须保留版权/许可声明，模型许可另行核对。

当前 FrameNest 用整段 RMS < 0.008 判断近静音，长窗口内短发声和低音量可能被均值稀释。直接拼接 VAD 语音块会破坏媒体时间与词时间戳映射；直接换模型也没有本机性能证据。

## 决定

### 只有最近窗口的本机诊断

- 仅内存保存一个结构化快照，不入 Room、不写日志、不导出、不上传，不包含 PCM、字幕文字、文件路径、凭证或媒体标识。
- 用单调时钟分别记录窗口模型就绪检查、PCM 读取/解码（含现有缓存/SMB 等待）、静音检查、ASR、MT、缓存/UI 提交，以及窗口处理总时长和互斥锁排队等待。不是 CPU 利用率，也不是完整应用启动时间。
- 初次模型下载/加载发生在 PlayerViewModel 准备阶段，**不计入**这里的窗口模型检查或首句就绪时间；音频阶段不能单独分解网络/解码/缓存命中成本。
- 原文和译文就绪时间从窗口开始计算，到对应 cue 持久化并提交 UI 状态为止；不是屏幕实际绘制时间。媒体迟到量为发布时最后一次播放器 tick 减 cue 起点，负值截断为零。预取 cue 因而可能是 0；播放器 tick 采样误差如实保留。
- 窗口落后量是**选中窗口起点**落后当前播放位置的媒体毫秒，不是所有待生成字幕的总量。维持一个在途窗口，不新建无界队列。
- 阶段耗时含失败尝试；未开始/尚未结束用 `—`，失败窗口明确标注。总处理时间不含另列的队列等待。缓存命中不伪造新测量。seek、音轨/语言切换、后台、关闭、退出清空快照；旧代次不能重新发布。
- 保持 RTF = 处理耗时 / 窗口媒体时长，有效 RTF 再乘播放倍率。没有采用 Handy 名为 `real_time_factor` 的相反比值，也不把媒体迟到量当作 wall-clock 延迟。

### 默认关闭的保守静音门控

- 播放面板显示“保守静音门控（实验，本次播放）”。只可在听译关闭且未准备时切换；每个新播放器会话回到默认关闭。
- 实验用 20ms 帧检查，至少 60ms 且所有 PCM16 样本都在 ±1 LSB 内才跳过整个窗口。任一更强样本即可放行，无最短语音起声阈值。空解码仍是可重试错误；太短或格式不支持时放行。
- **这是能量/近数字静音门控，不是语义 VAD，也不能识别人声或排除 BGM。** 音乐、噪声、不确定信号都交给 ASR。比旧 RMS 门控更保守，可能增加 ASR 工作和幻觉风险；不承诺提速或识别质量提升。
- 不删采样、不拼接语音块、不重采样、不改 PTS。将完整原数组交给现有 ASR，保留全部 750ms 上下文。纯函数无跨窗口状态，不新增 native 资源。
- 移除 Vosk 内部重复 RMS 判断；所有产品调用均通过 RealListenTranslateEngine 的既有/实验上游策略，默认行为不变，避免实验在 Vosk 路径被二次过滤。
- 实验的 ASR 缓存模型标识追加 `|silence-gate-v1`，默认标识完全不变。既有模型变更失效机制在两个方向都清理旧语言对生成缓存，避免旧的 RMS 静音覆盖挡住重识别。UI 提前说明切换后再启用会重新生成当前语言对字幕；无数据库迁移。

### 流式能力评估与后续门槛

- 当前 Sherpa 适配器使用 `OfflineRecognizer`，每窗口创建/解码/释放一个 `OfflineStream`。SenseVoice-Small 的这条接线没有可发布的增量流式状态，不能把分窗或 `createStream` 方法名宣传成真流式。
- Vosk 库按 250ms 块喂给识别器，但当前适配器收集结果后一次返回，而且每窗口重新建 recognizer。它具备后续研究部分结果的基础；当前没有跨窗口稳定词提交、回滚或迟到草稿隔离契约。
- 本次不添加未使用的流式接口或部分文字 UI。原文先显示的稳定 cue 回调继续工作，译文完成后更新同一范围。
- 后续真正的 capability gate 至少核实：精确模型/后端支持增量推理；稳定与可变结果的区分；原媒体时间映射；有界缓存和背压；seek/语言/音轨/后台/退出 reset/cancel/close；缺失能力时回落现有批处理；固定版本、下载校验、大小、模型许可证和 Android ABI。引入 Silero/Earshot 或新流式权重须另行确认分发/许可/体积，不默认下载。

## 验证与推广条件

单元测试覆盖纯门控极端/稀疏输入、PCM 数组和上下文时间映射、阶段计时、失败、源/译文独立就绪、2x 媒体延迟、实验开关和缓存身份。延续 FN-61 的 seek/后台/语言/音轨/退出回归。Compose 测试覆盖实验入口与诊断开关；AndroidTest 编译不能代替设备执行。

推广前需在手机和平板上，对相同片段/音轨分别记录基线与实验的首次加载、热窗口、短/轻声对白、纯音乐/音乐对白、seek、0.5x/1x/2x、后台恢复、连续播放温度/功耗/掉帧和字幕错误率。合成波形测试不是语音语料评估。当前没有 Android 真机加速证据，因此保持实验关闭。
