# 决策：有界快进请求与片尾重新打开

- 状态：accepted（实现与自动测试；真实 NAS 稳定性需补验）
- 日期：2026-08-31
- 任务：FN-50

> 拖动期间不再向播放器发预览定位，见 [0012](0012-scrub-preview-images.md)。本决策的有界队列仍约束松手落点、重播和加载超时。

## 问题与证据

用户反馈部分影片加载慢或失败、连续快进后更明显，以及片尾点击重新播放无效。

- 当前重播只调用 `setTime(0)` 和 `play()`，没有销毁已经 EOF 的 native input。
  [VideoLAN 的 VLC 3.0 实现](https://github.com/videolan/vlc/blob/3.0.x/lib/media_player.c)
  在 input 仍存在时只向它发送播放状态；`stop()` 才负责结束并释放该 input。
- FN-48 的 160ms / 400ms 门槛只限制触控提交频率，没有等待播放器处理上一目标。
  这不能保证 SMB 定位完成，也不能阻止待处理落点被旧进度覆盖。
- 旧实现用 400ms 的 EOF 忽略窗口猜测旧事件来源，同时在主线程调用 native stop。
  新媒体很短、重试频繁或旧输入停止缓慢时，时间窗口无法表达输入的真实寿命。

## 决定

1. 保留决策 0010 的拖动画面预览和松手最终落点；UI 仍使用原有节流。
   direct SMB 的 controller 再限制为一个已发送目标、一个可覆盖的最新待处理目标。
   时钟到达目标附近即允许继续；1500ms 没有确认时释放队列闸门，避免缺失事件永久
   阻塞后续定位。这个超时不代表 NAS 已完成读取，也不保证网络层不存在重叠请求。
   暂停态预览在 SMB 仍缓冲时不能因 750ms 计时到期而提前暂停或隐藏缓冲；保持静音解码，
   缓冲完成后重新启动短暂的帧稳定计时，缓冲始终不完成则由 30 秒加载超时报错。
2. 片尾重播立即进入 Preparing，在后台停止旧输入，再在主线程创建原媒体并从零播放。
   重播等待期间收到后台/音频焦点暂停，则首帧后保持暂停。旧快进到达片尾时如果已有
   更新的中段落点，重开后继续处理该最新目标。
3. 每次准备/关闭/错误都使旧 listener 失效。新的 listener 只在旧 input 停止后安装；
   已排入主线程的旧事件凭输入代次被丢弃，不再使用 EOF 忽略计数或 400ms 猜测窗口。
4. 重开与退出共用串行的停止时序；退出等待正在运行的 stop worker 后释放 native 对象。
   控制状态和释放快照统一在主线程，网络/解码器停止与释放在后台。
5. 首次准备和持续播放缓冲最长等待 30 秒后显示可重试错误，终止旧事件与排队 seek。
   不无限自动重连；用户可重试或退出。底层 native stop 若仍阻塞，后续重开仍需等待它，
   不能为了表面恢复而无限创建播放器或后台线程。

## 保持不变

- 决策 0007 的 direct SMB、硬件解码、凭证仅通过 options、无运行时数据路径 fallback。
- 本地文件 precise seek；SMB fast seek 和关键帧误差；缩略图/听译的数据路径。
- 拖动音量静音、播放画布布局、全屏和手势方向。

## 验证边界

队列单测证明请求合并和超时边界，不代替真实 NAS 吞吐测试。设备测试使用本地样本
验证 native 重播、换源和暂停恢复；真实 NAS 上长片、多次远距离快进及弱网恢复需单独
验收。未完成或索引损坏的文件仍不保证可播放或可 seek。
