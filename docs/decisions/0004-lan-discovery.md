# 决策：局域网 SMB 发现（两档）

- 状态：accepted
- 日期：2026-07-14
- 任务：post-MVP（非 FN 编号）

## 问题

手动填写 NAS 主机/IP 门槛偏高。是否做自动发现，以及用 mDNS、端口探测还是全协议栈。

## 证据

- 产品 MVP 明确不做「NAS 自动发现、DLNA…」（完整媒体库发现）。
- 家用 NAS：部分支持 `_smb._tcp` mDNS；不少设备只开 445 不广播。
- 全子网端口探测覆盖面大，但耗时/耗电，且结果噪声高。

## 决定

采用**用户主动触发**的两档发现，只填充「添加服务器」的主机字段，**不**自动填密码、不自动登录：

1. **默认**：mDNS/NSD 发现 `_smb._tcp.`
2. **可选深度扫描**：对当前站点本地 IPv4 子网探测 TCP **445**（宽前缀收窄到 /24，最多 254 主机）
3. 结果按 IP 去重合并；优先展示 mDNS 服务名

明确不做：NetBIOS 主力、DLNA/SSDP、静默后台扫描、云端上报。

## 未选择的方案

- **仅 mDNS**：实现轻但漏掉不广播的 NAS。
- **仅端口探测**：噪声与耗电偏高，缺少友好名称。
- **三条全上（含 NetBIOS/DLNA）**：边际收益低，维护与合规成本高。
- **静默全网扫描**：产品与权限风险不可接受。

## 后果

- 权限：`CHANGE_WIFI_MULTICAST_STATE`、`ACCESS_WIFI_STATE`（外加既有 INTERNET / ACCESS_NETWORK_STATE）。
- UI：服务器页「扫描局域网」；深度扫描为二次操作。
- `docs/PRODUCT.md`「MVP 不做」中的「NAS 自动发现」仍指完整媒体发现/DLNA；轻量 SMB LAN 扫描为 post-MVP 能力。
