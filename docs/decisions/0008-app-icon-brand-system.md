# 决策：FrameNest Logo 与应用品牌色体系

- 状态：accepted（FN-33 替代 FN-24 及 2026-08-12 早期视觉）
- 日期：2026-08-12
- 任务：FN-33

## 问题

FN-24 后曾先后采用黑白 `F` 字母块和“开放影框 + 编织托底”。两者在小尺寸下分别
存在视觉过重与符号像显示器/容器的问题，且应用仍使用旧蓝绿 Material 主题；Android 12+
默认动态取色还会完全覆盖固定品牌色。用户最终确认了蓝紫“旋转影框/光圈 + 中央播放”稿，
需要让图标资源、商店素材与手机/平板界面成为同一套品牌系统。

## 证据

- 确认稿保存为 `design/app-icon/framenest-logo-approved.png`，作为不可漂移的视觉母版。
- 1024 px、512 px、48 px 方形/圆形以及 Android 13 单色版本均完成视觉检查。
- 主题审计显示功能页绝大多数已消费 `MaterialTheme.colorScheme`；统一色彩角色即可覆盖
  服务器、浏览、最近播放、设置与面板，不需要逐页硬编码颜色。
- 原主题未显式提供多个 container/surface 角色，会混入 Material 默认紫灰色；现在已补齐。
- 对比度单测覆盖主要前景/背景组合，普通文字阈值为 4.5:1。

## 决定

1. 核心符号固定为四块向心旋转的圆角影框/光圈，中心深色负形托住暖白播放键；四个淡紫
   角标延续运动方向。它表达视频帧、播放与被聚拢的片库，不使用文字或字母。
2. 品牌源色固定为：Midnight `#0C122B`、Periwinkle `#7E7FF6`、Violet `#8D73E7`、
   Lavender `#B8B1F6`、Ivory `#FDF5E2`。
3. 浅色主题不能直接用 Periwinkle/Violet 承载白色文字；主操作使用加深的 `#5B56D5`，
   其余 Material 3 container、surface、outline 角色显式定义。深色主题可使用品牌源色。
4. `FrameNestTheme` 默认 `dynamicColor = false`，保证应用具有稳定品牌识别；调用方仍可
   显式选择动态取色，但产品默认不跟随壁纸替换品牌色。
5. 播放器未知视频背景上的黑白控制层、听译字幕黑底白字、错误色与 debug 诊断色保持功能
   语义，不强行品牌化。
6. `design/app-icon/generate_android_icons.py` 从确认母版确定性提取前景，并生成自适应前景/
   背景、旧版方形/圆形、Android 13 单色、Play Store 512 px 与 `docs/brand` 资产。

## 未选择的方案

- 继续使用蓝绿珊瑚编织影框：用户否决其整体形态与色调。
- 仅替换 Launcher 图标、不改主题：会让启动器与应用内部视觉继续割裂。
- 默认保留 Material You 动态取色：壁纸色会在 Android 12+ 覆盖品牌系统。
- 将所有黑白/错误色替换成蓝紫：会降低视频叠层和错误状态的语义与对比度。

## 后果

- 后续修改不得只替换某个密度或商店图；必须保留母版、运行生成脚本并检查全部输出。
- `framenest-logo-approved.png` 是 ImageGen 确认稿；生成脚本以明度边界提取其前景，避免
  手写几何近似导致形状漂移。
- Android 单色主题只保留符号 alpha，不保留蓝紫与暖白层级，这是平台着色的预期行为。
- 真机厂商遮罩、动态图标视差和不同壁纸下的观感仍需发布验收补测。
