# 决策：FrameNest 应用图标品牌体系

- 状态：accepted（替代 FN-24 初版图标视觉）
- 日期：2026-08-12
- 任务：FN-24 视觉迭代

## 问题

FN-24 初版采用薄荷渐变底、黑白 `F` 字母块与珊瑚弧线。大尺寸源稿有立体感，
但在启动器小尺寸下会收缩成厚重的黑白块；字母、播放键和底部弧线同时争抢注意力，
也没有稳定表达“影像被收纳并播放”的 FrameNest 产品含义。Play Store 图标仍停留在
更早一版，品牌资源之间也不一致。

## 证据

- 对 1024 px 源稿、512 px 商店图标、48 px `mdpi` 方形/圆形图标做了视觉检查。
- 新图标在 48 px 下仍保留三个可辨识层级：影框、播放键、编织托底。
- Android 13+ 单色资源使用同一前景 alpha，不依赖颜色表达轮廓。
- `testDebugUnitTest lintDebug assembleDebug assembleRelease` 通过，Android 资源可编译。

## 决定

1. 核心符号固定为原创的“开放式影框 + 两条编织环带 + 圆角播放键”：
   影框代表 Frame，交叠环带代表 Nest，播放键只承担一个暖色视觉焦点。
2. 品牌主色使用深海军蓝背景、天蓝到青绿的框体与环带、珊瑚色播放键；与应用已有
   Blue / Teal 色系保持亲缘，但不要求界面组件逐色复刻图标。
3. 保持扁平、粗轮廓、无文字和无细碎装饰。阴影只作为轻微层次，不改变符号轮廓。
4. `design/app-icon/generate_android_icons.py` 是唯一生成入口，同时产出自适应前景/背景、
   旧版方形/圆形、Android 13 单色、Play Store 512 px 与 `docs/brand` 资产。
5. Android XML 仅作为扁平矢量回退；正式启动器资源以确定性生成的 PNG 为准。

## 未选择的方案

- 延续黑色 `F` 字母块：小尺寸过重，且容易被识别为独立字母品牌而不是影像产品。
- 继续使用早期写实“画框 + 多层鸟巢”：亮边、阴影和多条细线在 48 px 下损失明显。
- 使用照片、AI 纹理或复杂 3D 材质：难以确定性重建，也不利于单色主题图标。

## 后果

- 后续修改不得只替换某个密度或商店图；必须运行生成脚本并检查全部输出。
- 主题图标只保证符号轮廓，不保留珊瑚播放焦点，这是 Android 单色着色的预期行为。
- 真机厂商启动器遮罩与桌面壁纸对比度仍需在发布验收中补测。
