# 决策：拖动预览改走 libVLC，回到前台要重新挂上画面

- 状态：accepted（实现与自动测试；真机出图和回到前台能否继续播放，以这次安装后的使用为准）
- 日期：2026-10-02
- 任务：FN-53

## 问题

进度条按住时，预览卡只有时间，没有那一时刻的画面。播放中切去别的应用再回来，画面停住，按播放也没有反应，必须退出播放页再进来。

## 证据

- 决策 0012 用一个 MediaMetadataRetriever 取拖动预览。同一批 NAS 上的大文件，列表封面走这条路径时描述符长度是 -1，接着是 FUSE `ENOBUFS`，取到的帧是空的。封面后来改成 libVLC 内存回调才出图。拖动预览仍停在取帧器上，所以手指下面没有对应画面。
- 播放页进入后台时，SurfaceView 的表面被销毁。libVLC 3.6.5 的 `AWindow.onSurfaceDestroyed` 会拆掉视频输出，并摘掉 SurfaceHolder 回调。`MediaPlayer.updateVideoSurfaces` 发现输出已经拆掉就直接返回。原来的回到前台只做了这次尺寸刷新，新表面没有人接，视频轨也画不出去。退出播放页会新建播放器并重新 `attachViews`，所以再进来就好了。

## 决定

1. 手指按住进度条或滑动时，仍不向正在播放的 libVLC 发 seek，也不静音。松手才提交一次落点。
2. SMB 的预览帧改由播放页里单独的一个软件解码 libVLC 取出。地址与播放相同，用 `Uri` 打开不含账号的 `smb://`。用户名、密码和域只作为媒体选项，字符数组用完即清，不写入日志。不挂窗口，用和封面相同的内存回调写一帧 `RV32`，再缩到长边 240。这个播放器在一次拖动里复用，按 10 秒桶 fast seek，不给每个桶新建连接。
3. 播放过程中不为 SMB 预热那 12 张分布帧，避免第二条 SMB 连接和正在看的片子抢带宽。手指按下才开始取，手指所在的桶优先，并且只保留一个在途提取。手指移到还没有画面的桶时，放弃当前这一桶，不把它记成失败。本地文件仍用原来的 MediaMetadataRetriever，播放中可以预热。
4. 磁盘缓存、10 秒分桶和「清理缓存」的 32MB 上限不变。一次拖动没取到的桶，下次按下可以再试。
5. 从别的应用回到播放页时，重新 `attachViews`。表面真正回来之后，若当时停在 Ready 或 Paused，再做一次原位置的静音取帧，把画面补回去。刚打开播放页时的 ON_START 不拆表面。播放仍按 0007 第 3 点走硬件解码。

## 未选择的方案

- 继续用 MediaMetadataRetriever 取 SMB 预览：这些文件上取不到帧。
- 拖动时 seek 正在播放的画面：0012 已经否掉，远程定位又慢又会把主画面拖走。
- 播放一开始就为整片预热预览：第二条连接会和播放抢 NAS。
- 只调用 `updateVideoSurfaces`：输出已经拆掉时它什么也不做。

## 后果

- 决策 0012 的第 3 点里，SMB 不再用 MediaMetadataRetriever。本地文件、松手定位、以及「拖动期间不 seek 主画面」仍然成立。
- 决策 0014 的已知长度仍给本地和其它仍走取帧器的路径。SMB 拖动预览不再打开代理描述符。代理 AFD 仍声明 `UNKNOWN_LENGTH`。
- 决策 0016 的封面路径不变。预览用的是另一个软件解码实例，只在播放页打开期间存在，不为文件夹每一行建播放器。
