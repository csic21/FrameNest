# 0023：听译原文先出与有效播放预算

## 状态

FN-61，2026-10-09。保留 SenseVoice/Vosk、ML Kit、本机缓存与当前播放默认行为。

## 背景

现有听译已按 3 秒窗口处理、缓存 PCM 与 cue，并按 12/30 秒范围预取。
但正常窗口必须等待 MT 才显示原文；成功窗口之后仍固定等待 500ms，实时率
又没有计算这段等待、缓存提交或实际播放倍率。后台暂停播放器不等于停止听译。

## 决定

- 在现有引擎接口增加可选的挂起进度回调。真实引擎识别出稳定原文后，在同一
  调用协程中发布并持久化源 cue，然后等待 MT 并替换同范围结果。空 MT 按失败退避，
  不反复立即重跑，也不误记为完整覆盖。旧引擎继续使用
  默认的一次性结果实现。仅译文模式仍遵守用户选择，不临时显示原文。
- 每次只有一个有界窗口；不增加线程池、并行识别器或脱离会话的翻译队列。
  成功窗口直接让出协程后检查下一个缓存缺口，无工作或失败退避时仍轮询等待。
- RTF 测量包括音频、ASR、MT、源/目标 cue 和进度提交，显示的有效 RTF 再乘
  实际播放倍率。1x 的 0.6 RTF 到 2x 是 1.2，应停止额外预取。
- 后台门控取消在途窗口并停止新窗口，保留启用意图与有效缓存；回来续接。
  未完成的模型准备另行取消，回前台才重试。SMB 句柄在后台异步中断，
  保留 owner 供前台重新连接；迟到的旧连接不得中止替换连接。已加载模型不因普通
  后台切换反复卸载。
- 每次取消、显式 seek（包括小幅 seek）、音轨/语言失效都更新窗口代次。
  源回调与最终结果发布前后检查代次、前后台及协程取消，并捕获不可变的缓存身份。
  同步 native 推理仍不能保证立即中断；旧结果不可发布，关闭继续在后台完成。

## 未做

不改变数据库、签名、版本、权限、NAS 数据路径或播放器自动播放行为。不新增
远端 ASR、Qwen、模型下载来源、字幕预缓冲 UI，也不承诺未经真机测量的延迟倍数。
流水线并行与源文跨目标语言共享缓存留到分阶段真机测量后再决定。

## 验证

使用虚拟时间覆盖原文先显示/落盘、最终替换、后台取消/恢复、后台启用、小幅 seek
后的不合作迟到回调、音轨缓存切换、退出后不重启、无固定空等、缓存提交预算与倍速。
完整 Android 构建依赖现有 CI；手机/平板、真实 NAS 和长期温度/掉帧仍需真机验证。
