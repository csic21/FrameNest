# 0027 听译首句与用户主动准备

- 日期：2026-10-11
- 状态：接受，FN-67；用户授权优化、推送 main 和发布。

## 决定

1. 音频缓存第一次请求和不连续 seek 只解码请求区间，连续相邻窗口恢复原有 6 秒预读。仍保留 3 秒 ASR 窗口和前后 750ms 上下文，不更换模型或 NAS 读取路径。
2. 仅原文以源语言到自身的语言对保存完成覆盖，使用 `source-only-v1` 翻译身份。切到双语/仅译文时切回用户选定语言对并重启窗口代次。由此避免把源文覆盖误当成译文已完成；不迁移数据库，也不伪造译文。不同模式的持久缓存暂不跨语言对共享。
3. MT 模型准备延后到原文发布后的翻译阶段，避免下载/准备阻塞原文。沿用用户的计费网络设置。只在当前引擎内保留最近一个已识别窗口的原文与时间，按窗口、源语言和音轨匹配；翻译失败重试或同窗口模式切换复用该结果。不新增音频持久化或后台队列。
4. SenseVoice token 保留空格/SentencePiece 边界，合并无新词边界的 Latin 子词，中文不插入额外空格。Vosk 仍按词间空格拼接。最短显示时长为 600ms，受当前窗口末尾限制；不改变 cue 起点、媒体位置或上下文裁切。ASR 缓存身份追加 `text-v3`，按现有机制使旧的错误组词/时长结果失效。
5. 在听译面板增加“暂停并准备后续字幕”。此动作暂停播放，并在前台准备从当前位置起约 12 秒连续覆盖；片尾按剩余时长裁切，按窗口对齐可略超过 12 秒。完成、取消、seek、切换语言/音轨、后台或继续播放都会退出准备状态。不会自动恢复播放。普通暂停仍只补当前窗口，网络缓冲仍暂停读取。
6. UI 显示的就绪量从当前位置连续计算，遇缺口或缺译文即停止；静音覆盖也代表已处理的媒体时间。它与预取目标、累计处理最远位置不同。平均处理持续慢于播放的设备仍可能耗尽准备量，本次不增加全片后台转写或云服务。

## 变更的已有决定

0023 的串行单窗口、原文先发布、取消代次继续适用；仅原文现在可独立完成，MT 准备从启用阶段移至翻译阶段。0023/产品范围中暂停不预取的默认行为保留，增加用户主动准备这一例外。0024/0025 的门控和媒体时间轴保持不变，缓存文本版本额外升级。

## 验证与局限

回归覆盖首窗/连续/seek/音轨读取预算、真实组词路径、短句时长、翻译失败复用、源文模式独立覆盖、切换/seek/后台取消、连续缺口和片尾、手机/平板尺寸控件。构建与设备结果记录在 FN-67 交接。没有真实 NAS、SenseVoice 语料准确率、温度或功耗对照，不承诺固定延迟和速度倍数。

Mac aapt2 校验记录来自固定版本 Google Maven HTTPS 下载，SHA-256 与本地缓存逐字节摘要一致；没有关闭依赖验证、升级工具链或修改签名。
