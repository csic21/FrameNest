# 实施计划

计划按依赖波次而非固定周数执行。每个任务保持可单独验收，完成一个波次后再开始
依赖它的任务。

## 依赖图

```text
FN-00 工程骨架
├── FN-01 播放内核 spike ──┐
├── FN-02 SMB 数据路径 spike ├── FN-05 SMB 播放纵切面 ─┬── FN-06 字幕
└── FN-03 自适应 App 外壳 ──┘                         ├── FN-07 缩略图/首帧
                         FN-02 ── FN-04 SMB 浏览 ─────┤
                                                       └── FN-08 平板打磨
FN-04 + FN-05 + FN-06 + FN-07 + FN-08 ──────────────── FN-09 稳定与发布
```

## 波次与并行方式

| 波次 | 可分配任务 | 进入条件 | 退出条件 |
|---|---|---|---|
| 0 | `FN-00` | 无 | 工程在 CI/本机可编译、基础检查可运行 |
| 1 | `FN-01`、`FN-02`、`FN-03` 并行 | FN-00 | 两份决策记录 + 手机/平板 App 外壳 |
| 2 | `FN-04`、`FN-05` 并行 | 对应 spike 完成 | 可浏览 NAS；可播放并保存进度 |
| 3 | `FN-06`、`FN-07`、`FN-08` 并行 | FN-04、FN-05 | 字幕、两类预渲染、平板体验完成 |
| 4 | `FN-09` | 其余任务完成 | 发布验收场景通过并产出测试 APK |

## 集成规则

1. 每个 Agent 使用独立分支/worktree，避免共享工作目录同时写文件。
2. 每个波次指定一名集成 Agent；功能 Agent 不争抢导航、版本目录和 Room 注册文件。
3. 合并顺序按任务编号；每次合并后运行 `assembleDebug` 和单元测试。
4. spike 分支只保留最小可运行实验和决策记录，不把临时代码直接扩成正式架构。
5. 发现跨任务阻塞时，先在交接中明确接口和文件，不顺手扩大任务范围。
