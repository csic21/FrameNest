# 性能与包体基线

## 拖动预览图（FN-51）

- 拖动进度不再对正在播放的 libVLC 发 preview seek。手指移动只更新本地时间和预览桶。
- SMB 预览由播放页里单独的一个软件解码 libVLC 取帧，只在手指按下后开始，不在播放过程中预热。本地文件仍用 MediaMetadataRetriever，播放位置附近优先，最多再铺 12 张均匀帧；缓冲时暂停预热。同一 10 秒桶只解码一次，替换文件靠 size/modifiedTime 换新键。
- 预览 JPEG 长边 240px，磁盘上限 32MB，超限时按修改时间删最旧的文件。清理一般缓存会删掉 `cacheDir/scrub-previews`。

纯 JVM 测试覆盖插队、缓冲不预热、失败不重试、最近帧选择和磁盘淘汰。没有连接真实 NAS，因此不记录单帧出图毫秒。

## 播放器无卡顿退出（FN-44）

PME110（Android 16 / API 36）安装 arm64 release 后，以真实 SMB 4K/60fps HEVC 片源从
“最近播放”进入播放并按系统返回。主线程在 3ms 内隐藏并移除视频输出；native stop 在
后台于 420ms 完成，随后主线程 detach views，最终后台 release 于 421ms 完成。释放顺序为
stop → detach → release，未出现 detach timeout，返回页在原生释放完成前已经恢复交互。

该次播放与返回期间共渲染 156 帧，UI 帧耗时 99 分位为 30ms；返回后 `MainActivity` 保持
resumed，FrameNest 没有活动媒体会话或继续播放的音频。这里的 420ms 是被移出主线程后的
资源清理时间，不是用户等待时间。

## 播放目录与缩略图 worker 复用（FN-43）

- SMB 视频首帧就绪后，外挂字幕候选和同目录上一集/下一集从同一份父目录文件名快照
  派生；首次播放的短连接、认证和目录枚举由各 2 次降为 1 次，播放随机读连接仍保持隔离。
- 每个缩略图 worker 延迟创建并复用一个代理 FD `HandlerThread`，不再为每张封面创建和
  销毁线程；线程数量现在受缩略图并发设置约束为 1–2，并随 worker 统一安全退出。
- 缩略图观察接口返回稳定的 `StateFlow`，视频行通过 `remember(entry, repository)` 固定
  观察对象，状态更新引发的 Compose 重组不再重复包装 Flow 和计算观察 key。

纯 JVM 测试验证共享目录文件名快照仍按语言偏好过滤、排序并生成正确的外挂字幕路径；
unit test、lint、debug/release 构建均通过。当前没有连接的 Android 设备或真实 NAS，
因此不记录未经测量的首帧毫秒数与滚动帧率。

## 听译初始化失败清理（FN-42）

- 听译准备失败或取消后，已创建的 SMB 音频源、Vosk engine 和 ML Kit translator 统一在
  `Dispatchers.IO` 关闭，不再从 `withContext(IO)` 返回后占用 ViewModel 主线程。
- 清理使用 `NonCancellable`，因此关闭页面或切换听译配置触发取消时仍会释放已创建资源；
  每个 close 独立 best-effort，一个 native/网络关闭异常不妨碍其余资源释放。

JVM 测试从已取消协程进入清理，验证三个资源都在指定后台线程关闭，并覆盖首个 close
抛错后继续执行后续清理。

## 缩略图磁盘计量与摘要（FN-41）

- JPEG 目录大小首次按需扫描后由覆盖前/写入后文件长度增量维护；未超过 80 MiB 上限时，
  后续每次 `put` 不再 `listFiles + sumOf`。容量真正超限才枚举并按 mtime 淘汰。
- 因此同一批 500 张未超限封面从最多 500 次全目录容量扫描降为 1 次；覆盖、删除、损坏
  JPEG、清理和写入失败分别更新、校准或失效计量。
- `ThumbnailKey` 在实例内缓存摘要；canonical input 不再创建临时列表，SHA-256 十六进制
  使用 `CharArray` 编码并只生成所需 32 字符，不再逐字节调用 Formatter 或先生成 64 字符。
- 缩略图目录从应用启动时立即 `mkdirs` 改为首次后台写入时创建；纯内存命中和没有缓存的
  冷启动不触发这次磁盘操作。

纯 JVM 测试以真实临时目录验证延迟创建、写入、覆盖、删除和清理字节数，并用扫描计数器
验证连续增量更新只扫描一次；SHA-256 结果通过标准 `abc` 向量校验。

## 听译窗口 Room 快速写入（FN-40）

- 会话 activation 已校验 content/model 并建立 job 后，语音 cue 使用“父行 touch + 同范围
  替换”事务，不再为每条 cue SELECT 父行并完整 `@Upsert`。
- 整窗空白/覆盖 cue 与 covered/status/duration 定向 UPDATE 在同一事务提交；ASR 语音原文
  仍先独立落盘，因此后续覆盖事务取消或翻译失败不会隐藏已完成文本。
- `updateProgress` 改为单条 SQL UPDATE，以 `MAX` 保持 covered 单调递增，并用 nullable
  参数保留未指定的 status/error/duration；父行意外被清除时 cue 快速路径会 ensure 后重试。

虚拟时间连续 10 个空白窗口从 20 次 job SELECT + 20 次完整 job upsert 降为窗口内 0 次；
全会话只剩 activation 的各 1 次，并执行 10 次定向进度 UPDATE。API 36.1 真实 Room 测试
验证语音、重叠覆盖、进度、外键和事务均通过。

## LAN 主动探测有界 worker（FN-39）

- /24 主动探测由“每个地址一个 `async` + 信号量”等待改为固定 worker 通过原子索引取下
  一个地址；默认 253 个目标只创建 32 个 worker，而不是 253 个探测协程。
- 最大在途 socket 仍为配置并发值，不改变 350ms 超时、地址范围、端口或用户主动触发
  约束；探测结束后再次检查取消，停止扫描不会发布迟到结果。
- Wi-Fi、以太网或 VPN 切换期间，单个 `NetworkInterface` 的状态/地址读取失败只跳过该
  接口，不再让整个本机 IPv4 枚举提前失败。

虚拟时间测试对 100 个地址验证最大并发严格为 7、每个地址恰好探测一次、结果完整且
取消向上传播；默认 /24 的 worker 数断言为 32。

## 设置页缓存维护 I/O（FN-38）

- `SettingsScreen` 首次 composition 不再同步遍历缩略图/字幕/诊断目录，也不再同步读取
  Vosk 安装状态；界面先创建轻量状态，再由协程加载统一使用量快照。
- `CacheMaintenance` 的 Room、文件和模型操作全部是挂起 API，并在维护层切到 I/O
  dispatcher；生产代码中的 4 处 `runBlocking` 已移除。
- “清除全部缓存”不再为了相减而在操作前后各遍历一次未清除的 Vosk 模型目录；“清除
  听译缓存”也不再扫描无关磁盘缓存和模型。每个按钮只统计自身影响的数据类别。

这消除了设置页首帧上的目录 I/O，并将普通缓存/Room 清理的 Vosk 大目录遍历次数从 2
降为 0；模型大小本身仍在后台按需统计，不用估算值冒充实际占用。

## 听译 PCM 解码分配（FN-37）

- MediaCodec 输出直接从只读 `ByteBuffer` 视图下混 PCM16/float，不再为每个输出块先
  复制一份同尺寸 `ByteArray`；转换不会移动 codec buffer 的 position/limit。
- 完整位于目标窗口内的 PCM 块不再执行 `copyOfRange`；源采样率已经是 16 kHz 时也不再
  `copyOf`。因此常见 PCM16/16 kHz 完整块从“1 个字节数组 + 3 个短整型数组”降为
  1 个下混短整型数组，再写入最终连续缓冲。
- 解码结果使用按目标时长预估的连续缓冲，不再把所有分块保留到末尾后统一拼接；常规
  3–9 秒且样本数与时长匹配时直接返回预分配 backing，长窗口仍有 10 秒预分配上限。

纯逻辑测试验证 PCM16/float 字节序、立体声下混、Buffer 状态不变、完整裁剪/16 kHz
数组复用，以及低估容量后的扩容顺序；实际 MediaCodec 内存曲线仍需真机 profiler 验收。

## 听译 cue 内存热路径（FN-36）

- `ListenTranslateSession` 使用 `upsertCue` 返回值更新按 `start_ms/rev` 排序的会话缓存；
  Room Flow 继续异步校准最终状态，但每个 3 秒窗口完成后不再 `listCues` 全量回读。
- 同时间范围严格替换，短语音片段与整窗覆盖记录可共存；翻译阶段失败时，已识别原文仍
  立即进入缓存和 UI。
- 当前字幕查找由两次 `filter` 临时列表改为单次无中间集合扫描，保持半开区间优先、
  更晚 start 和更高 rev 优先的既有语义。

虚拟时钟测试连续生成 0–30 秒的 10 个窗口，会话全程只执行 1 次初始化 `listCues`；
此前每个空白窗口额外 1 次、含短语音与覆盖记录的窗口额外 2 次全量查询。

## Room 迁移与听译写入（FN-35）

- 数据库不再使用缺少迁移路径时清空全部表的 destructive fallback；v1→v2 显式创建
  听译 job/cue 表和现有索引，服务器与播放历史原表保持不变。
- 提交由历史 v1 源码与当前 v2 源码生成的 Room schema；API 36.1 手机模拟器上的
  `MigrationTestHelper` 验证旧数据保留、最终 schema 匹配且新听译表可写。
- 连续听译窗口写 cue 时复用 `ensureJob` 已完成的主键查询，并移除紧随其后的重复
  parent touch。纯逻辑 DAO 计数测试确认每个普通 cue 从 3 次 job 查询、2 次 job upsert
  降为各 1 次；content key 与模型版本变化仍会删除旧 job/cue 后重建。

上述记录的是确定性的 SQL 往返次数与迁移结果，不将模拟器执行时间当作真机 Room 性能数据。

## 播放器返回释放（FN-34）

- 返回仍在主线程立即 detach/remove 视频画布，避免 SurfaceView 残留。
- libVLC 的 native `stop/release`、代理 FD 关闭和 `LibVLC.release` 在命名 daemon
  线程执行；`popBackStack` 不再等待远程输入和解码器停止。
- 退出进度快照、SMB/听译后台清理和幂等释放行为保持不变。

当前没有物理设备与真实 NAS，因此不记录虚假的返回帧耗时；真机验收需分别覆盖播放中、
暂停、断网和大码率远程视频返回。

## 文件夹视频封面（FN-52）

- 列表封面从 40dp 改为 128×72dp。取帧仍是每个 worker 一个 MediaMetadataRetriever，默认单并发。
- 长片的第一候选落在 30–120 秒内。只有这一帧是黑场或纯色时才继续后面的候选，最多 4 次。
- 新文件名带 `c2`。旧封面留在同一目录里，计入 80MB 上限，按最旧修改时间淘汰，不额外全盘扫描。

没有真实 NAS，不记录单张封面的毫秒数。

## 文件夹封面加载（FN-53）

- 列表封面默认 3 个 worker 同时取，每个 worker 复用一个 libVLC，直接打开不含账号的 SMB。播放器不挂窗口。长边 320，短边保持片子比例，格子里完整放入。先 fast seek 到 8 秒，这一帧仍是黑场或纯色再试 20 秒。单个文件最多 8 秒，出了可用帧立刻停止。不为每一行建播放器。
- 列表不再下载片头前缀。等待时格子里是电影图标，封面到位后短淡入。新文件名是 `c3`。被压成 16:9 的 `c2` 不再当作命中。
- 升级前的 `<digest>.jpg` 可以先显示，同时继续生成 `c3`。SMB 拖动预览不再打开代理描述符。代理 AFD 仍是 `UNKNOWN_LENGTH`。播放仍用硬件解码。

真机上，把完整大小交给代理取帧器之后，大文件仍然出现 FUSE `ENOBUFS`，随后四次取帧为空。64 MB 片头又只盖住了同一文件夹里的一部分，多部 2160p 仍是占位。这里不把那些失败间隔写成新路径的出图耗时。

## 可见区域优先的缩略图调度（FN-32）

- 待处理任务使用按 `generation + digest` 去重的有序队列，不再为每个条目向无界
  channel 累积一份不可撤销的工作。
- 一个条目的最后一份 UI interest 释放时，尚未开始的任务立即从队列移除；条目重新
  进入可见区域后可重新排队。已经开始的提取继续沿用 generation 校验、缓存写入和
  安全发布逻辑。
- 唤醒信号使用 conflated channel，排队信号数量不随快速滚过的条目数线性增长；
  单/双 worker、每 worker 一条 SMB 会话、失败退避与缓存数据路径保持不变。

纯逻辑单测覆盖 500 个离屏任务全部取消后，新可见条目直接成为下一项，以及排队/
在途去重、重新进入和清空行为。当前没有真机与真 NAS，因此这里只记录确定性的调度
行为，不虚报滚动帧率、首屏耗时或封面生成毫秒数。

## 自适应预翻译（FN-23）

- 调度优先级：当前播放窗口 → 领先范围内第一个缓存缺口。
- 以 `ASR + MT 耗时 / 音频窗口时长` 为实时因子，用 25% 新样本权重平滑：
  - ≤ 0.65x：预生成未来 30s；
  - 0.65x–1.0x：预生成未来 12s；
  - > 1.0x：只保障当前位置，不追加后台负载。
- 播放缓冲时中断在途预取；位置跨越至少 6s/两个窗口时视为远距离 seek，
  取消旧任务并立即调度新位置。
- 字幕与窗口覆盖行持久化到 Room，再次进入可继续扫描第一个缺口。
  音轨 ordinal 加入 content key，默认/未就绪状态与第 0 音轨稳定对应。

单测用虚拟时钟验证 0.5x 实时因子可连续填充 0–30s，并验证缓冲与
30s seek 会取消旧窗口。真机上的温度、电量和 NAS 带宽需继续观察。

## SMB 会话（FN-22）

- 目录浏览：同一服务器、同一连接配置下的连续 `load` 复用一条 SMB 会话。
  配置变更、客户端已断开或 SMB 操作失败后，下次操作重新认证。
- 缩略图：每个 worker 保持一条独立会话，不在并发 worker 间共享 `SmbClient`。
  因此同一服务器的 N 张连续缩略图从最多 N 次连接/认证降为每个活跃 worker
  通常 1 次（默认 worker=1，设置可选 2）。
- 密码不进入会话 key；仅新建连接时从凭证库取出，`connect` 返回后立即清零字符数组。

上述为可重现的连接次数改善，已由 fake client 单测验证连续浏览只连接一次。
真 NAS 的首屏时间、延迟与吞吐仍需设备验收，本文不虚报实测毫秒。

## APK 包体（2026-07-19）

干净构建，arm64-v8a + x86_64，release 已 R8/resource shrink。移除了对所有 `.so` 的
`keepDebugSymbols`；`libjnidispatch.so` 上游产物仍无法由 Android Gradle Plugin 剥离。

| 产物 | 修改前 | 修改后 | 变化 |
|---|---:|---:|---:|
| Debug arm64 | 102.3MB | 93.9MB | -8.4MB（-8.2%） |
| Debug x86_64 | 108.9MB | 100.9MB | -8.0MB（-7.3%） |
| Debug universal | 184.3MB | 168.7MB | -15.6MB（-8.5%） |
| Release arm64 | 79.6MB | 72.0MB | -7.6MB（-9.5%） |
| Release x86_64 | 86.3MB | 79.0MB | -7.3MB（-8.5%） |

Release universal 现为 146.8MB，同时包含两个受支持 ABI。修改前的 79.6MB universal
受 release `abiFilters` 与 split 不一致影响，实际只包含 arm64，因此不做虚假的同口径降幅对比。
内部真机分发应优先使用 arm64 分包；商店分发应使用 App Bundle 按 ABI 下发。
