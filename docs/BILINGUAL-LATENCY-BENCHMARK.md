# 映舟双语字幕对照实验

日期：2026-10-14。FN-70。本文是执行计划，没有手机/NAS实测结果。

## 第一组：确认当前优化的真实收益

同一部手机（用户所称 OPPO x9，实验前核实完整型号/SoC/系统版本）、同一 NAS、
同一网络位置、同一音频样本、同一音轨/语言对和 1x 播放。

A：当前基线的串行 MT 准备；B：非空/非静音 PCM 后 MT 准备与 ASR 重叠。
两种测试构建必须具有相同计时、窗口、预读、模型、线程数和构建优化，只切换这一个
调度差异。不要拿未经插桩的旧 APK 与新 APK 的不同指标直接比较。正式默认不增加
未经验证的模式开关；测试切换留在独立实验构建。此计划不授权发布、上传媒体或安装
未经用户确认的 APK。

现有并行范围：单个播放会话、单个在处理窗口、最多一个 MT 准备协程。没有跨窗口
ASR并发或无限翻译队列。取消会结束协程等待，并通过现有 ownership 关闭 Translator、
拒绝旧结果；SDK 下载 Task 本身可能继续，不保证网络/原生工作立即停止。

## 分组与控制变量

1. 已安装所有模型的冷开启：释放旧播放器/引擎后重新进入、在相同播放位置启用。
   至少20次有效尝试，记录首次非空 PCM、首次稳定原文、首次稳定双语发布以及首次
   双语选入当前叠层。按A/B交错顺序，避免整组A冷机、整组B热机。
2. 暖稳态：相同对白连续播放至少10分钟；每个有效窗口采样，单独统计预取领先、
   延迟和漏显，不能将空白/静音窗算作快速成功字幕。
3. 首次缺翻译包：与已安装模型分开记录，并列出网络下载准备时间；不能混入暖推理
   P50/P95。只在用户允许模型下载及网络条件合适时执行，不反复删除真实用户模型。
4. 恢复：相同远seek位置、后台停留后恢复、连续小seek各做对照。启动样本当前在
   seek/后台时失效；恢复延迟需独立从操作事件计时，不能误用原冷开启起点。
5. 本地文件对照：同一授权样本的本地副本用于区分NAS取流与ASR/MT；不自动复制
   用户NAS媒体到云端或公共存储。

保持固定电量区间/充电状态、音量、屏幕亮度、网络、温度起点；记录测试顺序及是否
热降频。测试前确认视频硬件解码和音轨一致。高分辨率视频、对白语言、音乐背景与
轻声样本分别报告，不把一个容易样本的结果泛化到所有片源。

## 指标定义

- 首条稳定双语：ASR最终原文及对应最终译文已完成发布，且不是临时 partial。
  同时报告“缓存就绪”和“当前叠层选中”；若已过期而未显示，后者为空并计入漏显。
  叠层选中是应用状态事件，不代表像素已经呈现。若需要真实呈现，另加渲染消费/帧
  时间验证，并说明误差。
- P50/P95字幕lag：对有语音且成功生成的字幕，用其对应媒体起点到双语就绪/选中的
  媒体时间差；保留提前量与迟到量区别。报告样本数、空结果、失败、超时和漏显率，
  不通过排除最慢/失败句子美化百分位。
- RTF：完整窗口 wall-clock / 窗口媒体时长；包含 PCM、ASR、MT准备等待、翻译、
  缓存提交，重叠阶段不能相加。冷启动准备单列，同时报告启用到首条双语总时长。
- 峰值内存：同一采样方式的进程 PSS/RSS 与峰值，记录采样周期；不要把模型文件
  大小当运行时峰值内存。Android上可用授权ADB的进程内存统计或Profiler。
- CPU/温升：同一采样周期的进程CPU、热状态/可获得的温度和播放掉帧/卡顿；注明
  系统可见性及采样开销。没有设备指标时留空，不用桌面CPU数字代替。
- 准确率：同一人工核对集的源文错误与译文可读性，重点看短句、专有名词、轻声和
  背景音乐。只缩小窗口但显著损伤词句，不算达成性能目标。

记录仅限匿名窗口序号、数值计时/统计、语言与模型版本、设备/构建信息。不得记录
音频、字幕正文、NAS地址、路径、账号或凭证。当前面板仅保留有界内存样本；P50/P95
需要独立、明确授权的测试采样，不把最近一窗伪装成分布统计。

## 第二组：流式 ASR 候选

在第一组定位瓶颈后，用相同音频和相同MT比较现有 SenseVoice 与经核验可用于 Android
的真正流式候选。Moonshine v2 是待验证候选，不能仅凭其他手机“句末处理延迟”就
宣称双语速度更快。模型下载/ABI/许可/体积/语言覆盖和时间戳必须先核验。

对真正流式方案分别报告 first partial、稳定前缀、句末final与最终双语。partial只放
会话内存；稳定前缀/终句才进入可复用缓存。MT做有界合并与修订号隔离，避免每个token
启动一次翻译引发排队和闪烁。NAS文件允许超前读取，另对比超前生成最终字幕与纯实时
麦克风式流处理，不能把耳机方案的延迟定义直接套用。

未授权自动下载新大模型、云端音频上传或引入收费服务。

## 判定

先看双语首句/稳态P95与漏显是否同时改善，再看CPU/内存/热与准确率有无明显恶化。
没有设备证据前不设“保证多少毫秒”的宣传阈值；根据真实基线和用户观感确定产品目标。
如果并行只改善首句而稳态仍由 PCM/ASR 主导，应继续对应瓶颈，不把第一组优化当终点。
